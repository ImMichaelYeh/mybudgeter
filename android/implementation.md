# Android Implementation Reference

Read [shared behavior](../implementation-shared.md) alongside this document. The approved implementation plan is saved in [plan.md](plan.md).

## App and build

- My Budget Planner is an offline Kotlin/WebView app in this repository's android/ folder. The separate MyBudgetPlanner repository is not used or modified.
- Gradle copies shared root HTML and src assets into generated assets before every build. Only a local snapshot of the portfolio masthead stylesheet is Android-specific; downloaded from its canonical URL on 2026-10-10.
- Launcher, page title, and header name are My Budget Planner with shared version 1.6.0, read directly from APP_VERSION during builds. Android versionCode is 5. The Android header omits the Michael Yeh masthead; the browser keeps its existing branding.
- Minimum Android version is 8.0 (API 26). WebView version 100+ and WEB_MESSAGE_LISTENER support are required; older providers show update instructions without touching the budget.
- Builds use JDK 17, Gradle 8.13, AGP 8.13.2, Kotlin 2.2.21, compile/target SDK 36, and pinned AndroidX dependencies.
- Assets load at https://appassets.androidplatform.net/assets/index.html?android=1 using WebViewAssetLoader. Native messages accept only the exact local origin and main frame. File/content access, mixed content, and non-asset resource requests are blocked; no INTERNET or broad storage permission is requested.
- External HTTP(S) portfolio links open in a system browser. JavaScript alerts/confirmations use native dialogs. WebView debugging and console logs are enabled only in debug builds.

## Phone interface

- Currency symbols follow the current Android language-and-region locale: en-US uses $, en-GB uses £, de-DE uses €, and other supported regions use their native currency symbol. The native Currency API supplies the currency code and JavaScript Intl supplies its localized narrow symbol. A locale without a supported currency region falls back to USD. Symbols are applied before the budget renders and refreshed on activity recreation. Language alone does not identify a currency; amounts retain comma grouping and two decimals, and no values are converted or rewritten. Browser backups contain the original amounts and display the currency symbol chosen by the receiving browser locale.
- Google Play translation does not automatically translate the bundled HTML/JavaScript interface. Store-listing translation and Android string-resource translation are separate; WebView UI translations require explicit localized strings. Currency display works offline without translation services.
- One vertical page preserves the shared section order, all six selectable summary periods, theme, colors, and functionality. Categories and form fields stack even in landscape; the selected summary totals use plain label/value rows with subtle line separators. Each category's selected-period Budget, Spending/Saving, and Remaining occupy three compact columns with labels above currency values. An 8-pixel progress bar sits below with its percentage beside it. This reduces the metrics area to roughly half its previous height at normal text size; labels and large amounts wrap, and enlarged text grows the area instead of being clipped. Desktop metrics retain their existing layout. Add Category is full-width beneath the categories with a plus icon and a 56-pixel minimum height. Android always uses one category column and has no Categories Per Row selector; the browser preference remains compatible with app backups.
- Compact gutters, wrapping labels/amounts, and zero cumulative subgroup margins prevent narrow-screen overflow. Action targets are at least 48 CSS pixels; group/menu buttons have accessible names, collapse buttons expose expanded state, and save/error messages use status/alert semantics.
- Menu options have a small visible gap. Items omit group-path tags and put amount/frequency beside the name, following the shared layout rules.
- Hamburger buttons match the collapse circle: 36 pixels visually within a 48-pixel touch target, with a compact 16-pixel icon.
- The Android footer reads "Having issues? Contact my.development.life@gmail.com"; the browser retains its copyright footer.
- Item names and amount/frequency summaries share a compact row with one hamburger menu; long text wraps within its column. Group headers keep one hamburger menu beside the larger left-aligned name, followed inline by the selected Budget Period amount/frequency in regular-weight text. The collapse circle is 36 pixels visually within a 48-pixel touch target; the name sits immediately to its right. Names and totals wrap within the space between collapse and menu buttons only when needed. Items and groups omit percentages under the shared summary rules.
- Inputs request decimal keyboards. New entries retain scroll-into-view behavior and focused controls scroll above the keyboard. Android text size follows the system font scale.
- Compact Export Save File and Import Save File buttons sit side by side, retaining 48-pixel touch targets. The subtitle is omitted and buttons sit directly below the title, with save status beside the title and backup help below the buttons. Section names and Tap To Collapse/Expand controls share a row, wrapping only when needed for enlarged text or narrow space. Income, Budget Board, Notes, and FAQ use Tap wording and preserve their saved section state.
- Category names and Budget/Actual percentages share the header with one compact hamburger menu. Long names and percentage text wrap within the left column; controls retain 48-pixel touch targets. Category editors still span the full card width.
- Category menus offer Move, Edit, Color, and Remove. The shared Color dialog retains 48-pixel touch targets and closes without saving on Back.
- Android removes native HTML drag attributes, grips, and ordering arrow bars. Hold a category header, item name/details, or group name for 350ms, then drag. Ordinary swipes scroll. Categories use top/bottom quarter drops for insertion and center drops for swapping; item/group edge drops reorder and center drops group/nest entries. Dropping on category space moves an item/group to its root. A compact, noninteractive ghost of the held entry follows the finger, showing its name and details without action buttons; it disappears after a drop or cancellation. Target labels show the operation, invalid self/descendant drops are unavailable, and holding near screen edges scrolls. Cancellation or Back leaves the budget unchanged. Unsaved editors require discard confirmation before a valid drop commits. Focusable names also support Alt+Up/Down sibling ordering with keyboard focus retained; drag/reorder outcomes are announced through a status region. Menu Move for items/groups remains reserved for transfers to another group or category, including leaving a group, with searchable full paths and no position selector or item targets. Category Move chooses another category and Before/After/Swap; it is disabled when only one category exists. Income has Edit/Remove.
- Invalid self/descendant destinations are rejected. Same-name destination groups retain all items under the shared group-path convention. Moved subtree collapse preferences follow their new paths; similarly named groups are left alone.
- Category edits commit on Save; Cancel leaves existing category values unchanged. New category cancellation removes the draft card. Browser live category autosave remains browser-specific.

## Storage, backups, and lifecycle

- Budget JSON is stored in app-private budget.json through AtomicFile. One serial queue spans activity recreation, preserving prior files on failed replacements and preventing out-of-order writes.
- Committed Android changes save promptly and flush on background/exit. Failures retain working changes and provide retry. Missing data starts with default categories; unreadable data is preserved and offers Retry Loading/Import Backup.
- Native document pickers use OpenDocument/CreateDocument with JSON files. File-picker cancellation is harmless. Imports validate in shared JavaScript, confirm replacement, and persist before switching. Pickers survive recreation using retained request identifiers and a private cached result. Export errors are reported.
- Imported files are limited to 16 MiB to bound memory use. The schema remains MyBudgeter-budget-v1; browser/app backups round-trip without automatic sync.
- Android system bars, cutouts, and keyboard insets are respected. Back dismisses the keyboard first, then panels/dialogs; editors confirm unsaved discard. Ordinary Back checkpoints and exits.
- A separate private session.json stores editor field values, current edit identities, and scroll position. Recreation restores drafts only when their underlying budget data matches the committed budget, preventing stale session data from replacing a newer import/save.
- Automatic cloud backup and device-transfer backup are disabled. Clearing app data/uninstalling removes budget and drafts; deliberate JSON exports remain the backup mechanism.
